# KCU105 runtime — running a program over JTAG-to-AXI (no XRT)

This is the host-side replacement for XRT. Status: **board-validated** — exercised
end-to-end on real xcku040 (`gronau.local`): a trivial run and a full **MIPS32 simulation
to `$finish`** (see `VERIFICATION.md` / `CHANGES.md`). The control-register sequence and
the boot-stream *container* format are verified against source and on silicon.

> **[Updated 2026-06-30]** The **validated host runtime is `vivado/kcu105/run_manifest.py`**
> (reads `manifest.json`, lays out global memory like `manticore-runtime`, emits `image.mem` +
> a `run.tcl` with the FLUSH→cache-flush→resume loop). The `run_kcu105.tcl` + `gen_image.py`
> pair described below is the **earlier scaffold** — kept for the simple control-sequence
> reference, but `run_manifest.py` is what ran MIPS32 to completion.

## Pieces

- **`vivado/kcu105/run_kcu105.tcl`** — programs the `.bit`, loads the image into BRAM over
  JTAG-to-AXI, writes the control registers, starts the device, polls `ap_idle`, and reads
  back `ExceptionId` / cycle counts / a memory word.
- **`vivado/kcu105/gen_image.py`** — emits the BRAM image (32-bit hex words) from per-PE
  programs, in the exact format the on-chip bootloader reads.

## Memory map (from the block design)

| region | address | notes |
|---|---|---|
| gmem BRAM | `0x0000_0000` (256 KiB) | `DramBank0Base` is set to `0x0` |
| `s_axi_control` | `0x0010_0000` | only the JTAG master reaches it |

> **[Updated 2026-06-30]** The gmem BRAM is **internal to the kernel** (`TrueDualPortBram` via
> `GmemBramBackend`), not an external block-design memory backing a kernel DRAM master. The
> external `axi_bram_ctrl` simply fronts the kernel's exported **GMEM** port, so the host AXI
> window is unchanged: gmem still appears at `0x0`.

## Control sequence (run_kcu105.tcl)

1. Read `DeviceInfo` (0x24) → check `DimX`/`DimY` (`(v>>26)&0x3f`, `(v>>20)&0x3f`).
2. Write the image into BRAM (32-bit beats at `0x0 + i*4`).
3. `DramBank0Base` (0x90, 64b) = `0x0`.
4. `GlobalMemoryInstructionBase` (0x84, 64b) = boot-stream offset.
5. `ScheduleConfig` (0x6c, 64b) = `(1<<63) | timeout` (start command).
6. `Control` (0x00) = `1` (ap_start).
7. Poll `Control` bit2 (ap_idle) / bit1 (ap_done).
8. Read `ExceptionId` (0x10; 0 = ok), `CycleCount` (0x2c), `VirtualCycleCount` (0x38),
   and the result word from BRAM.

## Boot-stream image format (verified vs Programmer.scala)

All 16-bit words; per PE, repeated `DimX*DimY` times (x fastest, then y):

```
[ (dest_y<<8) | dest_x ]
[ body_length ]                       # number of 64-bit instructions
[ inst[15:0] ][ inst[31:16] ][ inst[47:32] ][ inst[63:48] ]   # ×body_length
[ epilogue_length ]                   # expected number of receives
[ sleep_length ]
```

The **countdown** phase is generated by the hardware bootloader — it is **not** in the
image (Programmer.scala `Phase.StreamCountDown` reads no memory). Two 16-bit words pack
little-endian into each 32-bit BRAM word.

## Board bring-up items (P4) — RESOLVED on real xcku040

> **[Updated 2026-06-30]** These were the open P4 items; all are now settled on `gronau.local`
> (details in `CHANGES.md`). Kept here as history.

- **Addressing units.** ✅ Confirmed on-board: `GlobalMemoryInstructionBase` is a 16-bit-word
  offset; `DramBank0Base` is the byte base (both 0 in the trivial/MIPS32 runs).
- **Trivial program.** ✅ A 2×2 NOP program booted, ran the BSP schedule, and hit the timeout
  (`VirtualCycles=2000`); then MIPS32 ran end-to-end to `$finish`. `run_manifest.py` produces
  the image from a compiled `manifest.json` (the validated path).
- **JTAG hw_axi name / clocking.** ✅ `hw_axi_1` live; `s_axi_control` reached at `0x0010_0000`.

## Quick start

> **[Updated 2026-06-30]** The **validated** path runs a compiled benchmark via
> `run_manifest.py` (this is how MIPS32 ran to `$finish` on the board — see `VERIFICATION.md`
> for the full reproduce recipe). The `gen_image.py`/`run_kcu105.tcl` snippet below is the
> earlier hand-rolled scaffold for a trivial NOP program.

```bash
# validated: compiled benchmark via the manifest runtime
python3 vivado/kcu105/run_manifest.py <manifest.json> <build>/.../system_wrapper.bit

# earlier scaffold (trivial NOP image):
python3 vivado/kcu105/gen_image.py --dimx 2 --dimy 2 -o image.hex   # prints instr_base_words
vivado -mode batch -source vivado/kcu105/run_kcu105.tcl \
  -tclargs <build>/manticore_kcu105.runs/impl_1/system_wrapper.bit image.hex 2048 0
```
